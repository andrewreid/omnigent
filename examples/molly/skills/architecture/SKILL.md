# Conditional architecture

Orchestrator only. Load dispatch and send one bounded, read-only `explore` task
to a strongest suitable available reasoning model. Do this for costly-to-reverse
decisions, material ambiguity, substantive disagreement or failed convergence;
not as a ceremony for every change.

Supply the goal, contract, constraints, evidence and exact decision needed. Ask
for options with tradeoffs, a recommendation, invariants and unresolved risks.
Do not ask for a file-by-file implementation recipe. A diagnosis should explain
why prior work failed and the smallest justified next step. Give the result to
the implementer as decisions and constraints. Human input is needed only when
the decision changes authorized scope, behavior, cost, risk or preferences.
